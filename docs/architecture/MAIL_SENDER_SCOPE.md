## Observed provider state and owner-approved change

- The signed-in Purelymail Account Admin portal initially had **Restrict who users can send as** selected. It had an exact allow rule from `booking@didde-mie.com` to `noreply+booking@didde-mie.com` (prefix matching off) and an **all-users Default Purelymail rules: Allow** rule. The latter explicitly permitted a user's own symbolic subaddresses when the domain feature is enabled. [Purelymail's sender-policy guide](https://support.purelymail.com/support/solutions/articles/159000433207-error-530-5-7-1-you-x-are-not-authorized-to-send-mail-as-y-) describes authorization of both envelope and visible From.
- The live Routing page shows **Symbolic Subaddressing enabled** for `didde-mie.com`. This contradicts the earlier checkpoint claim that it was disabled. The enabled feature and then-default send-as rule explain the prior accepted `booking+unapproved@didde-mie.com` probes on both new booking process credentials. This is an inference from the policy and observations, not a fresh SMTP test. [Purelymail's subaddressing guide](https://support.purelymail.com/support/solutions/articles/159000406702-symbolic-subaddressing) warns that disabling the feature stops tagged inbound delivery.
- The booking user's app-password list shows distinct `booking communications` and `booking worker` entries plus older `controlled mail` and `contact form` entries. Names and last-used indicators do not prove which systems still hold the older secrets. App passwords can be revoked individually, but Purelymail states they give full mailbox access; they are not process-specific send-as policies.
- In the repository, production booking communications and worker are the only booking application SMTP consumers. Booking web rejects SMTP credentials. Hosted Pretix has historically remained on Mailpit, and the primary service is not part of booking hosting. Local active process files are capture-only; `infra/local/retired-booking.env` still has legacy SMTP fields and must remain private. The current VPS runtime configuration needs a fresh owner-sudo inventory.
